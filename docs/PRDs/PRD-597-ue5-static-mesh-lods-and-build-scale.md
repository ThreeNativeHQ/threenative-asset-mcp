# PRD-597 — UE5 static mesh LODs and BuildScale3D

**Status:** NOT STARTED
**Priority:** P2 — AC-1..AC-4 open: UE 5.4+ meshes with a non-unit `BuildScale3D` import at the wrong size, and UE5 static meshes give LOD0 only.
**Complexity:** 2 (LOW) — 1–5 files (`src/unreal/cue4parse-adapter.ts`, `src/unreal/importer.ts`, `src/unreal/mesh-build-scale.ts`); risk override: none.
**Owner:** unassigned
**Depends on:** None

## Context

**BuildScale3D.** `readBuildScale3D` (`src/unreal/mesh-build-scale.ts:61`) scans the package bytes for the tag. It
accepts legacy headers -7 and -8 (tests `tests/unreal-palms-paragon.test.ts:222,288`), so UE 5.0–5.3 work. It fails on:
- legacy -9 headers (UE 5.5+, `PACKAGE_SAVED_HASH` = 1016): rejected at `mesh-build-scale.ts:22`, and the header
  offsets at :24-28 move;
- the UE 5.4+ property tag (`PROPERTY_TAG_COMPLETE_TYPE_NAME` = 1012): a type-name tree and a flags byte replace the
  old tag, so the layout check at :68-84 never matches;
- it takes the first match in the package, not `SourceModels[0]`.
The result is applied at `src/unreal/importer.ts:5309` through `geometryScaleFor` (:1306). In the engine the value is
`UStaticMesh::SourceModels[i].BuildSettings.BuildScale3D` (`StaticMesh.h:657`, `StaticMeshSourceData.h:161`,
`EngineTypes.h:3009`). The adapter already reads `SourceModels` as `FStructFallback[]` (`cue4parse-adapter.ts:2373`),
and CUE4Parse handles every tag layout it supports.

**LODs.** `ExportStaticMeshAsync` (`cue4parse-adapter.ts:2312`) writes LOD0 only on both branches: the cooked branch
(:2335) passes no `meshQuality`; the editor branch (`ExportEditorStaticMesh`, :2355) keeps the largest parsable
FMeshDescription payload (:4681-4707). Skeletal meshes already emit `Meshes/<name>_LOD<n>.glb` when `--lods` asks
(:2467-2500), and the importer promotes those to `Models/<name>_LOD<n>.glb` (`importer.ts:5278-5289,5359,5414`).
An editor LOD often has no payload of its own: Unreal generates it at build time from `ReductionSettings`. Only
payloads that exist can be decoded.

## Solution

1. Read `BuildScale3D` in the converter from `SourceModels[0].BuildSettings` and write it into the mesh export
   metadata. The importer uses that value for the modern route and keeps `readBuildScale3D` for the UE4 routes.
2. Cooked UE5 static meshes follow the skeletal path: honour `--lods` with `EMeshQuality.All` and write `_LOD<n>` GLBs.
3. Editor UE5 static meshes: map each `SourceModels[i]` that has its own payload to that payload and write it as
   `_LOD<n>`. A source model with reduction settings and no payload is reported as "generated by Unreal at build time;
   not decoded", never faked.
